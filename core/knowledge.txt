================================================================================
OWNCODE KNOWLEDGE GUIDE — core/ (Core IDE Runtime, Lifecycle & LSP Engine)
================================================================================

1. PURPOSE OF THIS FOLDER
-------------------------
The `core/` folder is the central nervous system of OwnCode IDE. It handles:
  • Application startup validation, profiling, and background initialization
  • The global publish/subscribe EventBus that connects the UI, Tools, and Agent
  • Workspace folder loading, file watching, and safe atomic file operations
  • Editor buffer/tab state management and external file modification detection
  • Language Server Protocol (LSP) client management and in-process Python Jedi
    code intelligence (autocomplete, hover, definitions, and diagnostics)
  • Transparent module alias resolution (`core/__init__.py`) so consolidated
    modules and legacy module paths resolve seamlessly.

2. LIBRARIES USED IN `core/`
----------------------------
  • PySide6 (QtCore, QtWidgets) : Qt signals, QObject, QThread, QTimer, and
                                  QFileSystemWatcher (with pure-Python headless
                                  fallbacks when running CLI tests).
  • importlib / sys / types     : MetaPathFinder & Loader for virtual module
                                  aliasing across consolidated files.
  • logging / logging.handlers  : Rotating file and console loggers.
  • threading / queue           : Thread-safe event dispatch and background tasks.
  • pathlib / os / shutil       : Cross-platform filesystem and atomic file writes.
  • json / tempfile / time      : Session persistence, config validation, profiling.
  • jedi (optional)             : In-process Python static analysis & completions.

3. MODULES, CLASSES & FUNCTIONS IN `core/`
------------------------------------------

[1] core/__init__.py
    Role: Initializes the `core` package and installs `_ConsolidatedFinder` on
          `sys.meta_path` so all consolidated modules across `core/`, `agent/`,
          `ui/`, and `tools/` can be imported by either their new canonical name
          or their original submodule path.
    Classes:
      • _VirtualPackage
        Key Methods: __init__
      • _ConsolidatedLoader
        Key Methods: __init__, create_module, exec_module
      • _ConsolidatedFinder
        Key Methods: find_spec
    Functions:
      • install_import_aliases()

[2] core/event_and_compat.py
    Role: Combines the Qt compatibility layer (`qt_compat`), central logging
          (`logger`), custom IDE exception hierarchy (`exceptions`), and the
          publish/subscribe `EventBus` (`event_bus`).
    Classes:
      • OwnCodeError — Base exception for all application errors.
      • ModelTimeoutError — Raised when an AI model takes too long to respond.
      • ToolExecutionError — Raised when a tool (e.g., terminal, file) fails to execute.
      • ConfigurationError — Raised when configuration is invalid or missing.
      • ProviderError — Raised when a provider operation fails.
      • EventBus — Manages pub/sub event distribution across the app.
        Key Methods: __init__, subscribe, unsubscribe, publish
    Functions:
      • namer(name) — Custom namer for rotated log files.
      • rotator(source, dest) — Custom rotator that compresses rotated logs with gzip.
      • setup_logger(name, log_level, log_dir, max_bytes, backup_count) — Creates and configures a standard logger for a module.
      • get_logger(name) — Get an existing logger or create a new one with default settings.
      • set_global_log_level(level) — Set the log level for all existing loggers.
      • clean_old_logs(log_dir, keep_days) — Clean up log files older than the specified number of days.

        Key Methods: __init__, start, stop, send_request, send_notification

    Functions:

4. HOW `core/` CONNECTS TO THE REST OF OWNCODE
----------------------------------------------
  • `main.py` creates `EventBus()` from `core/event_and_compat.py` and passes it
    to `MainWindow` (`ui/`), `WorkspaceManager` (`core/`), `RunManager` (`tools/`),
    and `AIChatEngine` (`agent/`).
  • All cross-layer communication happens through `event_bus.publish(event, data)`
    and `event_bus.subscribe(event, callback)`, keeping `ui/`, `tools/`, and
    `agent/` decoupled.
